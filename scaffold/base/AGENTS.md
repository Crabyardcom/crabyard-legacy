## Backend And IPC Patterns

- All Rust commands return `AppResult<T>`.
- Register every command in `src-tauri/src/lib.rs` with `tauri::generate_handler!`.
- Add every command to `CommandMap` in `src/lib/tauri.ts`.
- Export a typed wrapper from `src/lib/tauri.ts`; React components should import wrappers, not `invoke`.
- Use `#[serde(rename_all = "camelCase")]` on Rust models shared with TypeScript.
- Mirror shared Rust models in `src/lib/types.ts` using camelCase field names.
- Keep `Mutex<AppState>` lock scopes short. Never hold the lock across slow I/O or network work.
- Map backend failures into `AppError` instead of returning raw strings or panicking.
- Update `src-tauri/capabilities/default.json` when a new Tauri plugin requires permissions.

## Add A Tauri Command

1. Create or extend a Rust command module in `src-tauri/src/commands/`.

```rust
use crate::error::{AppError, AppResult};
use crate::state::AppState;
use std::sync::Mutex;
use tauri::State;

#[tauri::command]
pub async fn do_something(
    state: State<'_, Mutex<AppState>>,
    input: String,
) -> AppResult<String> {
    let _state = state
        .lock()
        .map_err(|err| AppError::Other(err.to_string()))?;

    Ok(format!("Result: {input}"))
}
```

2. Export the module from `src-tauri/src/commands/mod.rs`.

```rust
pub mod myfeature;
```

3. Register the command in `src-tauri/src/lib.rs`.

```rust
tauri::generate_handler![
    commands::myfeature::do_something,
]
```

4. Add the command contract and wrapper in `src/lib/tauri.ts`.

```typescript
type CommandMap = {
  do_something: [{ input: string }, string];
};

export async function doSomething(input: string): Promise<string> {
  return invokeCommand("do_something", { input });
}
```

5. Use the wrapper from React.

```typescript
import * as api from "@/lib/tauri";

const result = await api.doSomething("hello");
```

If the command exchanges structured data, add the Rust type in `src-tauri/src/models/`, export it from `models/mod.rs`, and mirror it in `src/lib/types.ts`.

## Auth, Settings, And Updates

- `{{AUTH_MODULE}}` is the selected auth overlay. If it is `none`, do not invent login state unless the user asks.
- For GitHub or Google auth, keep login/logout/restore behavior in `useAuth.ts` and the matching Rust auth commands.
- Store user preferences in `AppSettings` and update both `src-tauri/src/models/settings.rs` and `src/lib/types.ts`.
- Use `useSettings.ts` rather than duplicating settings persistence in components.
- Keep updater behavior in `useUpdater.ts` and `UpdateBanner.tsx`.
- Updates stay disabled until signing keys, release artifacts, and an endpoint are configured; see `docs/PRODUCTION.md`.

## Environment And Secrets

- `.env` is local and gitignored.
- `.env.example` contains placeholders and is safe to commit.
- `VITE_` variables are exposed to frontend code.
- Backend-only secrets must not use the `VITE_` prefix.
- Do not hardcode tokens, OAuth secrets, API keys, or filesystem-specific paths in frontend code.
- OAuth client IDs are public identifiers. Never embed client secrets in a desktop binary.
- The starter auth overlays use a local JSON token store; replace it with an OS credential manager or encrypted vault before distributing an authenticated product.
